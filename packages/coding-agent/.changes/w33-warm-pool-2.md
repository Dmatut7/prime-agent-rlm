- Warmed the warm spare pool's create path: a spare now runs one throwaway in-memory session build (settings/auth/models/extension reads plus tool assembly, telemetry off) and a refused self-auth probe before it starts listening, so claiming it no longer pays the per-process first-create cost (~60-80ms). `PRIME_AGENT_INTERNAL_WARM_SPARE_WARMUP=0` disables the warmup.
- Changed warm-pool claims during warm-up from an immediate cold miss to a bounded wait (default 750ms, `claimWarmingWaitMs` option): a create arriving while its spare is still warming claims it once ready, and only a warm-up that fails or outlives the wait falls back to a cold launch. Spare warm-up failures are now a recorded terminal state with the failure reason logged and a per-cwd spawn cooldown that a successful warm-up clears.
