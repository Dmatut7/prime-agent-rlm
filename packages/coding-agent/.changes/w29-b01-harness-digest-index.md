- Changed the harness digest to a two-layer face: the per-kind relevance window stays, and every entry beyond the window is now named in a compact id+title index (byte-capped at 12 KiB by default, `harness.digestIndexMaxBytes` setting) instead of an anonymous `+N more` line.
- Added a write-side index byte cap: a harness create/update that would grow the id+title index past the cap is refused with consolidation guidance (deletes and content-only updates always pass), so the store converges to a size whose full index fits the digest; `0` disables the gate, and the kernel honors `PRIME_AGENT_HARNESS_INDEX_MAX_BYTES`.
- Added write receipts for memory near-duplicates on the `/refine` path (parity with the kernel's wave-26 advisory) and for entry paths outside the controlled first-segment vocabulary (`harness.pathVocabulary` setting; kernel: `PRIME_AGENT_HARNESS_PATH_VOCABULARY`).
