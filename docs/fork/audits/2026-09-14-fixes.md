## UI-1（P2，**修复中**）粘贴里含字面 `ESC[201~` ⇒ 粘贴被截断、尾部**按按键执行**
`stdin-buffer.ts:402` + `editor.ts:745`（两层同规则）。实证：`\x1b[200~abc\x1b[201~\x1b[1;5Ctail\x1b[201~` ⇒ `pastes=["abc"]`、`data=["\x1b[1;5C","t","a","i","l",…]`（**ctrl+right 真的会执行**）。正控：同长度正常粘贴 1 paste / 0 data。
即"粘贴进来的字节可以被解释成按键"——只要有剪贴板含原始 ESC 字节（发生率 unverified）。

## UI-2（P2，**修复中**）超限/超时/非括号大输入被**逐字符**送进编辑器 ⇒ 单行插入 O(n²) 卡死
`stdin-buffer.ts:413-415`（8MiB 上限）/`:489-497`（30s 看门狗）+`:204-217`，消费侧 `editor.ts:1178/1209`。
实测：200k 字符 feed = **8.2s**、1M = **257s**、100k 单行 = 5.1s（开/关 onChange 同值 ⇒ 主因是整行复制）。机制正控：`pasteMaxBytes=1000` 探针下超限粘贴产生 700 个逐字符 `data` 事件，正常粘贴 0 个。
触发面：慢链路大粘贴（1MB@30KB/s ≈ 33s 就超时）与 >8MiB 粘贴。

## UI-3（P3）`truncateToWidth(pad=true)` 对窄行（ANSI + 宽字符/ZWJ 簇）宽度算错
`utils.ts:1190` 按 ANSI 就地分段累加，而 `visibleWidth` 先剥 ANSI 再分段 ⇒ 同一串两种口径：`truncateToWidth("❤️\x1b[31ḿ",15,"...",true)` 宽 14、ZWJ 家族+ANSI 差 2、随机 45/80000 例；正控（无 ANSI 插入簇内）恰好 15。可见后果仅 `menu-panel.ts:366/371` 右端少格。

**负结论（带正控，措辞是"本次扫描未破"而非"没问题"）**：组件宽度不变量 0/4000（含 CJK/emoji/表格/长 URL）；尺寸变化 0/10（含 CJK 高转录 + 边追加边 resize）；标记跨块切分 25/25 对；CJK/emoji 光标对位正确；正常括号粘贴 1M = 27ms。
