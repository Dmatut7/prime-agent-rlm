# 持续审查流水线（PIPELINE）

老板令：持续审、泛范围审、多模型验证、确认的写进带日期修复文档。目标是项目长期稳定（开发层面不出问题、长期工作不退化）。

## 循环结构
1. **发现轮**：并行派 N（4~6）条 **DeepSeek v4.1 Flash** 审查线。每条只给"角度 + 纪律 + 产出格式"，**不给范围上限**（项目大且是 AI 项目，不同角度才审得出不同的问题）。允许自己决定看哪里、跟着线索走。
2. **对撞轮**：发现轮报回后，把每条结论交给 **千问 3.8 Flash**（对抗：找反例、能否打穿）与 **Kimi K3**（深审：该不该算问题、有没有更根本的解法）。两边都站得住才进档。
3. **成档**：确认的条目写进 `docs/fork/audits/<日期>-*.md`（带日期、证据、影响、修法、状态）；同时追加一行到 `decisions.jsonl`。
4. **修复**：红测 → 补丁 → 绿 → 全仓检查；在独立 worktree 里做，不污染主工作区。
5. **心跳**：每 30 分钟推进一轮（收线 / 派线 / 并档 / 修缺陷），从不空转。

## 派活纪律（每条线都要带）
- 只读：不许改仓库（产出写 /tmp/audit_r/<round>/<lane>.md，心跳写同目录 <lane>.heartbeat）
- 证据纪律：不许把注释当证据；"不存在/无影响"必须附正控；验不了写 unverified
- 冻结 SHA：本轮 = 审查时点的 HEAD，命令写死 SHA 不用 HEAD
- 收尾必须回话给 parent（≤12 行）：Top 结论 + 证据路径 + 未完成项
